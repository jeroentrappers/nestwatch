# Open questions

Implementers record here every place where the specs are ambiguous,
incomplete or contradictory, with the interpretation they chose. The spec
owner resolves each entry by changing the specs and removing it here.

| ID | Spec section | Question | Interim choice |
|----|--------------|----------|----------------|
| FFI-1 | architecture.md §5 | How do PCM samples and camera pixels cross the UniFFI boundary? `Vec<i16>` becomes a boxed `List<Short>` in Kotlin. | As byte arrays: interleaved little-endian PCM (`push_capture_i16`, `push_capture_f32`, `push_talk_capture`, `pull_playback`, `pull_talkback`), the native layout of `AudioRecord`/`AudioTrack` and `AVAudioPCMBuffer`. Camera images are tightly packed RGBA, RGB or I420 (full-range BT.601) plus a clockwise rotation; lull-ffi converts and rotates to the engine's RGB/RGBA `CameraFrame`. |
| FFI-2 | architecture.md §5 | Delivery of snapshots to foreign UIs ("bounded rates"). | Foreign `StationObserver`/`ListenerObserver` callbacks on lull-ffi's own tokio threads: at most one snapshot per 100 ms (latest wins), plus a 1 s heartbeat while a pairing window is open so countdowns move; events and video frames as they happen (lagging frames dropped). Snapshots carry `remaining_ms` instead of the engine's monotonic `closes_at_ms`. |
| FFI-3 | protocol.md §3.2, §3.5 | Apps that list interfaces themselves (Android) must give endpoints before the engine binds, but the port is only known after binding with fallbacks. | lull-ffi probes 47100..47109 for a port free on IPv4 and IPv6, then binds exactly that port and builds invitation endpoints from the app's interface list with the core's ordering rules. A port taken between probe and bind fails the start. |
| ANDROID-1 | platforms.md §2.1, §2.2 | lull-core's mDNS (`mdns-sd`) and interface listing (`if-addrs`) call `getifaddrs`, which bionic only has from API 24; the library would not load on Android 6. | lull-net builds neither on Android (Advertiser/Browser report unsupported). The station advertises through `NsdManager` with the TXT data from `StationSnapshot.mdns_txt`, re-registering on change (NSD cannot update TXT). The listener browses with NSD under a `MulticastLock`, resolves one service at a time and reports results with `Listener.add_discovered` (new `ListenerEngine::add_discovered`/`remove_discovered`). Interface addresses come from `java.net.NetworkInterface`. |
| ANDROID-2 | security.md §5 | Details of "encrypted with an Android Keystore AES-GCM key". | One AES-256-GCM Keystore key (`org.lull.storage.v1`, no user authentication, since a station runs unattended). Each storage value is a file `noBackupFilesDir/lull/<name>.sealed` = version `1` ‖ 12-byte IV ‖ ciphertext+tag, AAD = the storage name, written with `AtomicFile`. Backups and device transfer are disabled and excluded in the manifest rules. |
| ANDROID-3 | platforms.md §2.2, security.md PRIV-4 | The camera foreground service type must be declared when the service starts (API 34 also needs the permission then), but the camera is only wanted later, possibly with the screen off; and an unattended station cannot ask for the permission when a listener first opens the view. | The station asks for the camera permission (with an explanation, optional) when the user starts the station. The service declares `microphone` plus `camera` (if granted) from the start on API 30+, plain on API 23–29. Without the permission the station reports camera availability `denied`. |
| ANDROID-4 | platforms.md §2.2 | Which foreground service type covers listener talk-back, and when does the listener service run? | The listener service (type `mediaPlayback` on API 29+) runs whenever this device has the listener role, from app start until the role is changed. Talk-back captures the microphone only while the user holds the button in the visible app, which Android allows without a `microphone` service type. |
| ANDROID-5 | product.md FR-WEB-1, protocol.md §3.3 | Must an Android station serve the browser listener? | Not in v1: the Android station serves TCP only (no HTTP/HTTPS/WebSocket and no bundled web app). Browser listeners need a desktop station. |
| ANDROID-6 | media.md §2, product.md NFR-BW-1 | Opus on Android needs libopus cross-built for every ABI. | lull-ffi builds lull-core without the `opus` feature on Android for now; sessions use the baseline codec. |
| ANDROID-7 | product.md FR-ST-4 | What does "dimmable to near-black" do to the backlight and screen timeout? | Dim mode switches to the `.dimmed` palette, sets the window brightness to 1 % and keeps the screen on until tapped; without dim mode the screen may turn off normally while the service keeps monitoring. |
| ANDROID-8 | product.md FR-AL-1, FR-AL-4 | Alerts when notifications are not permitted (API 33+ denial). | Sound and connection alerts then play a short tone on the alarm stream from the listener service; with permission they are high-importance notifications (channels `alert-sound`, `alert-connection`; battery on `alert-battery`, default importance). |
