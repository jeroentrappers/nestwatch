# Open questions

Implementers record here every place where the specs are ambiguous,
incomplete or contradictory, with the interpretation they chose. The spec
owner resolves each entry by changing the specs and removing it here.

| ID | Spec section | Question | Interim choice |
|----|--------------|----------|----------------|
| MEDIA-1 | media.md §1.1 | Can the AGC attenuate (gain below 0 dB) when input is louder than -24 dBFS, and what counts as a "loud event"? | AGC gain stays within 0..+24 dB and never attenuates. Every frame at or above -70 dBFS (input, before gain) is treated as an event: desired gain = clamp(-24 − level, 0, 24). |
| MEDIA-2 | media.md §1.1 | How are frames below -70 dBFS handled by the AGC? | They pass at 0 dB (with a ramp back up on the next louder frame) and do not change the AGC state. |
| MEDIA-3 | media.md §1.1 | Exact attack behaviour ("within 50 ms") | Gain decreases apply to the whole frame that triggered them (≤ 20 ms); increases ramp linearly inside a frame and are limited to +0.06 dB per 20 ms frame (3 dB/s). |
| MEDIA-4 | media.md §2.1 | How does the encoder choose `step_index`, and must decoders reject a non-zero reserved byte? | Reference encoder: predictor = sample 0; step_index = the index (0..88) minimising squared coding error over samples 1..31, ties to the lowest; no state carried between frames. Decoders ignore the reserved byte and reject step_index > 88 or a length other than 164. |
| MEDIA-5 | media.md §2.2 | Is "6 dB per repetition" exact or a halving? | Exact: gains 10^(−6n/20) (0.501, 0.251, 0.126), rounded to nearest. |
| MEDIA-6 | media.md §3, protocol.md §6.1 | Where does `seq` start for a listener, which frames can be pre-roll, and how are pre-roll and hold times rounded to frames? | `seq` = captured frames since the gate (session) was created, starting at 0. Pre-roll covers ceil(preroll_ms / 20) frames but never frames captured before the session or frames already sent. A frame is held while (frames since last loud frame) × 20 ms ≤ hold_ms; the first frame beyond closes the gate and is not sent. |
| MEDIA-7 | media.md §3, protocol.md §6.1, §7.5 | Flags and `activity` on mode switches and continuous mode | Pre-roll frames carry only the pre-roll flag; the trigger carries first-of-burst; in continuous mode any frame not directly following the last sent one (session start, mode switch) carries first-of-burst. Continuous mode sends no `activity`. Switching continuous → activated keeps the gate open with the hold armed at the last sent frame (it later closes with `activity {open: false}`); activated → continuous sends no `activity`. |
| MEDIA-8 | media.md §4.1 | When does the faster-than-real-time burst end, what is "concealable silence", and what if a long loud burst has no silence? | Frames flagged pre-roll / first-of-burst and following frames arriving > 5 ms faster than real time are excluded from jitter. Target delay is measured from the smoothed mean transit (EW 1/16). Excess delay is skimmed one frame per pull from non-pre-roll frames at or below -50 dBFS or 12 dB below the recent average level; if excess persists 1 s without such frames, one frame is dropped every 60 ms. Target growth is applied immediately by inserting concealment frames. After 3 missing frames with nothing buffered the buffer goes idle (silence). |
| MEDIA-9 | media.md §4.2, product.md FR-TB-2 | Is talk-back "muting" of the talked-to station full mute, and how is volume expressed? | Full mute with a 20 ms ramp; volume is linear 0..1; station levels are measured before volume, mute and solo. The limiter is a static curve: identity to -3 dBFS, tanh knee above. |
| MEDIA-10 | media.md §5 | How do fps and quality steps combine on the ladder, where does it start for a `max_fps` not on the ladder, and which night gamma? | Each replacement moves one level: 15/70, 10/70, 7/70, 5/70, 3/60, 2/50, 1/40, 1/30 (quality drops on steps landing at ≤ 3 fps, then extra 1 fps levels to 30). The top level is the highest ladder rate ≤ max_fps (15 if above). One level up per 5 s without replacement. Night filter: BT.601 luma with tone curve out = in^0.6. YUV input is treated as full-range (JFIF) BT.601. |
