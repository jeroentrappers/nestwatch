# Open questions

Implementers record here every place where the specs are ambiguous,
incomplete or contradictory, with the interpretation they chose. The spec
owner resolves each entry by changing the specs and removing it here.

| ID | Spec section | Question | Interim choice |
|----|--------------|----------|----------------|
| PLATFORM-1 | security.md §5 | Windows asks for a DPAPI-protected file; DPAPI needs `unsafe` FFI that the workspace forbids, and the Credential Manager limits blobs to 2560 bytes, which a trust store can outgrow. | Secrets are files sealed with XChaCha20-Poly1305 under a random 32-byte wrapping key held in the Credential Manager (`sealed` store, AAD = secret name). Same user-scope protection as DPAPI. |
| PLATFORM-2 | security.md §5 | Linux "Secret Service when available, else a 0600 file": what happens to secrets written to the file while Secret Service was unavailable, once it becomes available? | Reads try the OS store, then the file store; writes go to the OS store and remove any file copy; deletes remove both. Secrets written to the OS store are not visible on a later run without it. |
| PLATFORM-3 | security.md §5 | Naming of stored secrets is unspecified. | Names are `[a-z0-9._-]{1,64}`, not starting with `.`. OS stores use service `org.lull.Lull`, account = name; files are `<data dir>/keys/<name>.secret` (`$XDG_DATA_HOME/lull/keys` on Linux), directory 0700, files 0600, atomic replace. |
| PLATFORM-4 | platforms.md §2.4 | Which sleep is inhibited, and should the screen stay on? | Idle and explicit sleep are inhibited (logind `sleep:idle` block locks on Linux, via keepawake, falling back to a `systemd-inhibit` child); the display may turn off. |
| PLATFORM-5 | protocol.md §7.7 | Desktop cameras have no front/back. Which camera does `video-options camera` select? | Facing is guessed from the device name: built-in ("Integrated", "Built-in", "FaceTime", "front") is `front`; "back"/"rear" is `back`; others are unknown and match neither. `back` also matches external cameras. Without a match the first camera is used. |
| PLATFORM-6 | media.md §5, protocol.md §7.7 | V4L2 lists metadata nodes and infrared sensors as video devices. | Only nodes that offer a colour capture format are cameras (grey-only IR sensors are not listed). |
| PLATFORM-7 | security.md PRIV-2 | Without a notification service a log-only fallback is needed, but alert titles and bodies name stations. | The log fallback records only that an alert of a given urgency could not be shown, never its text. |
| PLATFORM-8 | protocol.md §7.6, product.md FR-AL-3 | What does `charging` mean for a full battery or one held at a charge limit on mains power? | `charging` = on external power: a mains/USB supply is online, or the battery reports charging (or full when no supply node exists). Multiple batteries combine by energy; peripheral batteries (sysfs `scope=Device`) are ignored. |
| PLATFORM-9 | media.md §1, platforms.md §1 | Linux lists PipeWire, PulseAudio and ALSA; which path is used? | When `pactl info` succeeds, audio goes through the sound server with `parec`/`pacat` (16-bit, server-side resampling, client name `Lull`); otherwise cpal (ALSA) when built with the `cpal` feature. Playback through a pipe is paced by the wall clock with 40 ms lead; the pipe is shrunk to 4 KiB so device clock drift adds at most ~128 ms of latency; underruns are those `pacat --verbose` reports. |
